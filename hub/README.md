# مركز الحسابات والنشر (Accounts Hub)

قاعدة مستقلة على الـ VPS: سجل حسابات متعدد (جوجل/ووردبريس) + مواقع (بلوجر/ووردبريس/صفحات هبوط) + نشر يومي بثلاث جولات + أرشفة + تقرير + رفع على GitHub.
بلا Chrome ولا كمبيوتر: النشر عبر API رسمي بتوكن كل حساب (OAuth) مشفّر في القاعدة.

## البنية
| ملف | الدور |
|---|---|
| `src/db.js` | SQLite (accounts, sites, articles, writes, runs, gsc_issues, events) |
| `src/adapters/{blogger,wordpress,landing}.js` | واجهة نشر موحّدة `publish(site, account, article)`؛ أضف منصة = ملف واحد |
| `src/generators/commercial.js` | مصدر المواضيع (خطة الشراء التجارية + مولّد المقالات الحالي، صفر توكن) |
| `src/generators/personas.js` | 7 أنماط تفكير تغيّر ترتيب الأقسام والعناوين ونبرة الدعوة، ويُسند نمط لكل موقع |
| `src/diversity.js` | بوابة الجودة: ≥1200 كلمة، لا ادعاءات غير موثقة، 3 روابط طلب، ولا تشابه مع مقال آخر (بصمة 4-كلمات) |
| `src/planner.js` | توزيع اليوم على 3 جولات، التناوب، نسبة 70% تبريد/تكييف و70% مكة، حد 15 كتابة/ساعة/حساب |
| `src/runner.js` | تنفيذ جولة: مقال واحد/موقع، توقف عند 403/429، حساب `needs_login` عند انتهاء التوكن |
| `src/gsc.js` | تقديم sitemap وقراءة أخطائها إلى `gsc_issues` |
| `src/report.js`, `src/gitsync.js` | تقرير يومي (md + webhook) ورفعه إلى `hub/reports/` |
| `src/scheduler.js` | 06:30 · 13:00 · 20:30 نشر، 09:00 Search Console، 23:30 تقرير (توقيت الرياض) |
| `ui/index.html` | لوحة الحسابات والمواقع |

## ربط حساب جديد
اللوحة → اكتب اسماً → «ربط حساب جوجل» → توافق بنفسك على شاشة جوجل → يُحفظ refresh token مشفراً → «جلب مدوناته» يسجل كل مدونات الحساب. الحسابات تُفتح يدوياً؛ النظام لا ينشئ حسابات ولا يتخطى CAPTCHA.

## متطلبات جوجل (مرة واحدة)
Google Cloud: تفعيل Blogger API و Search Console API؛ OAuth client نوع Web؛ redirect `https://<HUB_DOMAIN>/oauth/callback`؛ نشر التطبيق (In production) كي لا تنتهي التوكنات بعد 7 أيام؛ وضع `GOOGLE_CLIENT_ID/SECRET` في بيئة المشروع.

## الجودة بدل التحايل
البوابة ترفض المقال القصير أو المكرر أو المحمّل بأرقام/تقييمات غير موثقة، والتنوع الحقيقي (أنماط، أحياء، زوايا، أقسام AI اختيارية) هو الهدف. حدود Blogger تُحترم، ولا تُستخدم الحسابات لتجاوزها.

## الاختبار
`node hub/src/selftest.js` (بدون شبكة).

## واتساب + الذكاء الاصطناعي (ربط المصدر)
1. اللوحة ← «خطوط الواتساب»: الصق الأرقام بلا أسماء، ثم قائمة الأسماء، ثم «توزيع عشوائي»: كل خط يأخذ اسماً عشوائياً وكل موقع يأخذ خطاً (حمل متوازن ±1).
2. كل مقال/صفحة فيها زرّان «راسل <الاسم> على واتساب» برابط `wa.me/<رقم الموقع>?text=…(مرجع: R9Y6SB)`.
3. البوت (إضافة ووردبريس الحالية) يقرأ المرجع من أول رسالة ويسأل الـhub:
   `GET https://<HUB_DOMAIN>/bot/ref/R9Y6SB` مع `Authorization: Bearer <HUB_BOT_TOKEN>` ← يرجع الموقع والمنصة والمقال والخط وجملة `assistant_note` جاهزة للبرومبت.
   وإن وصلت رسالة بلا مرجع: `GET /bot/line/<الرقم>` يرجع المواقع المرتبطة بالخط.
4. يرد البوت من نفس الرقم الذي جاء منه العميل (الجلسة نفسها)، فلا التباس بين المواقع أو الأسماء.

## التنويع
252 وصفة عرض = 7 أنماط تفكير × 6 ترتيبات للصفحة (الموقع أولاً / المقال أولاً / الشرح ثم الموقع / بطل مختصر / الأسئلة أولاً / قائمة العلامات أولاً) × 3 صيغ (رسمي / نظامي بالبنود / ودّي) × طولين.
الوصفة الأقل استخداماً على مستوى الشبكة تُختار لكل مقال. صفحات الهبوط نوع منفصل بهيكل وطول مختلفين (حد أدنى 350 كلمة).
