# OXY — Oxygen Maintenance WordPress Package

مستودع واجهة **OXYGEN** وإضافة ووردبريس لنشر مقالات صيانة المكيفات وتحديث المقالات المؤهلة.

## مكونات المستودع

- `oxygen-wp-theme/`: قالب WordPress فعلي لواجهة أكسجين والصفحات والمقالات.
- `index.html`: نسخة احتياطية ثابتة للواجهة فقط عند عدم وجود تثبيت WordPress في جذر الاستضافة؛ يجب أن تكون أولوية WordPress أعلى عند وجوده.
- `articles/`: صفحات المقالات الثابتة وقائمة المقالات.
- `scripts/publish_static_articles.py`: مولد/ناشر المقالات الثابتة مع التحقق من الجودة ومنع تكرار العناوين والكلمات المفتاحية.
- `.github/workflows/generate-static-seo-articles.yml`: نشر مقال واحد يوميًا الساعة 04:19 بتوقيت مصر، مع تشغيل يدوي لدفعات 1 أو 3 أو 5 مقالات.
- `oxygen-ac-automation/oxygen-ac-automation.php`: إضافة ووردبريس، بوابة الإدارة، ناشر المقالات والجدولة.
- `oxygen-ac-automation/includes/class-oxygen-business-control.php`: مركز إعدادات المؤسسة، الخدمات والأسعار والعروض والوسائط وطرق الدفع والتعليقات وذاكرة الإعدادات وربط Search Console.
- `oxygen-ac-automation/assets/oxygen-maintenance-home.html`: ملف الواجهة الكامل المعتمد، ويتضمن نافذة الإعدادات داخل الصفحة.
- `oxygen-ac-automation/assets/page-part-*.txt`: أجزاء احتياطية مضغوطة تتولد تلقائيًا من ملف الواجهة الكامل.
- `build-plugin.py`: أداة إعادة بناء الواجهة وأجزاء النسخة الاحتياطية مع الحفاظ على نافذة الإعدادات.

## تثبيت الإضافة

1. يجب أن يكون هناك تثبيت WordPress فعلي في مجلد النطاق الذي سيشغّل الإضافة، مع ملفات النواة وقاعدة البيانات.
2. ارفع الإضافة بعد التأكد من وجود نسخة احتياطية، ثم فعّلها من لوحة WordPress.
3. الإصدار الحالي لا يعيّن الصفحة الرئيسية تلقائيًا ولا يعترض كل طلبات الواجهة؛ يجب إدراج الشورت كود `[oxygen_ac_home]` في صفحة تحددها أنت، أو استخدام قالب `oxygen-wp-theme` بعد مراجعته.
4. رابط `/oxygen-admin/` منفصل عن نافذة الإعدادات المصممة داخل HTML. لا تفترض أن بوابة الإدارة أو لوحة الناشر متاحة حتى يستجيب WordPress فعليًا على نفس النطاق.
5. نافذة الإعدادات داخل HTML محفوظة كواجهة أصلية، لكنها تعتمد حاليًا على JavaScript في المتصفح؛ لا تعتبر كلمة المرور المضمّنة حماية حقيقية، ولا تفترض أن التعديلات ستُحفظ في قاعدة بيانات WordPress أو تظهر على أجهزة أخرى.

## الشات بوت والطلبات (المرحلة الأولى)

- `oxygen-ac-automation/includes/class-oxygen-orders-chat.php`: نقطة REST عامة `/wp-json/oxygen/v1/chat` تتكلم مع Claude نيابةً عن العميل، تفاصل داخل حدود الأسعار، وتسجل الطلب النهائي وترسله للمالك على واتساب (Cloud API). يعمل بالكامل داخل ووردبريس بدون VPS أو سيرفر خارجي.
- `oxygen-ac-automation/assets/oxygen-chat-widget.html`: قالب واجهة الشات (زر عائم ونافذة بشكل تطبيق، مشاركة الموقع). يُحقن قبل `</body>` عبر الفلتر `oxygen_ac_home_html` (والقالب عبر `oxygen_ac_chat_inject`) ولا يظهر إلا بعد التفعيل وضبط المفتاح.
- الإعدادات من لوحة ووردبريس: **الشات بوت والطلبات** (تحت إعدادات المؤسسة): المفتاح، تعليمات المالك، الخدمات `الخدمة|السعر|أقل سعر`، الفنيون `الاسم|الجوال|lat|lng|المنطقة`، وبيانات واتساب.
- الطلبات تُحفظ في قائمة **طلبات أكسجين** (للمدير فقط)، وحد أدنى للسعر يُفرض من السيرفر ولا يُكشف للشات، وحد 40 رسالة/10 دقائق و5 طلبات/يوم لكل عميل.
- ملاحظة واتساب: الرسالة النصية التلقائية تصل فقط خلال 24 ساعة من آخر رسالة أرسلتها لرقم الأعمال؛ للإرسال في أي وقت استخدم قالبًا معتمدًا من Meta بمتغير واحد.
- النسخة الثابتة `index.html` لا تحتوي الشات (تحتاج ووردبريس فعليًا).

## الجدولة اليومية

- يمكن ضبط حتى **30 مقالة إرشادية جديدة يوميًا**.
- يمكن ضبط حتى **30 مقالة SEO خدمية إضافية يوميًا** بعناوين متعددة؛ يجب أن تقدم محتوى مفيدًا يستهدف نية بحث مميزة لا نسخ الصفحة نفسها.
- يمكن ضبط حتى **30 مقالة قديمة مؤهلة يتم اختيارها عشوائيًا للتحديث يوميًا**.
- النشر التلقائي في ناشر ووردبريس متوقف افتراضيًا على التثبيت الجديد. وحتى إذا فُعّل، لا يُنشر المقال الجديد إلا إذا نجح توليد محتوى OpenAI؛ عند غياب المفتاح أو فشل التوليد تُحفظ المقالات كمسودات للمراجعة.
- يستخدم النظام WP-Cron. لضمان عمله حتى عند قلة الزيارات، اضبط Cron من Hostinger ليستدعي `/wp-cron.php?doing_wp_cron=1` كل 5–15 دقيقة متى كانت الخطة تسمح.
- تحديث المقال القديم يضيف معلومات ذات صلة ويحافظ على عنوانه ورابطه الدائم، ولا يعيد نشر النص نفسه كما هو. قد يكون العدد الفعلي أقل إذا لم تتوفر مقالات قديمة مناسبة أو عناوين فريدة. حجم النشر العالي لا يضمن الفهرسة، ويلزم فحص الجودة والروابط وخريطة الموقع.

## توليد المحتوى وSEO

يستخدم النظام قوالب عربية داخلية عند عدم ضبط مفتاح API، مع عناوين فرعية مرقمة، ومقدمة وخلاصة وأسئلة شائعة، وكلمات مفتاحية ووصف مختصر وحقول شائعة لـ Yoast SEO وRank Math. يمكن إضافة مفتاح OpenAI API اختياريًا من إعدادات الإضافة لتوليد نصوص مختلفة، وقد تترتب تكلفة على الاستخدام الخارجي.

**مهم:** 40 إجراءً للمحتوى يوميًا (20 جديدًا + 20 تحديثًا) لا يضمن تحسن الترتيب. تجنّب المقالات المتشابهة، وراجع دقة معلومات الخدمات والأسعار والتوافر؛ الجودة والمنفعة للمستخدم أهم من العدد.

## الخصوصية

لا تضف كلمات مرور أو مفاتيح API أو أرقام حسابات بنكية إلى مستودع عام. أُزيلت بيانات الدفع من ملف الواجهة. نافذة الإعدادات داخل الصفحة محفوظة كما صُممت، لكن رمزها المضمّن في JavaScript ظاهر لمن يستطيع الاطلاع على المصدر، لذا هو قفل شكلي فقط وليس آلية مصادقة آمنة. إعدادات النشر الدائمة تُدار من لوحة ووردبريس بصلاحية `manage_options`.

## استعادة الواجهة محليًا

بعد تنزيل المستودع كاملًا، شغّل:

```bash
python build-plugin.py
```

يعيد السكربت بناء النسخة المضغوطة وأجزاء النسخة الاحتياطية انطلاقًا من ملف HTML الكامل؛ ويحافظ على نافذة الإعدادات داخل الصفحة. تُزال بيانات الدفع الحساسة من الواجهة، ويُترك ملف الإضافة الحالي دون استبدال.


## مركز إدارة المؤسسة

- الإعدادات تحفظ في `wp_options` مع صلاحية `manage_options` وnonce للتحقق من طلبات الحفظ.
- يتم تمرير البيانات العامة الضرورية فقط إلى الواجهة؛ مفاتيح OAuth لا تُرسل للزوار، وتعليمات المساعد الخاصة لا تُضمّن في إعدادات الواجهة العامة.
- ذاكرة الإعدادات المؤقتة تستخدم Transients API مع مدة قابلة للضبط وإبطال ذاكرة الإضافة عند الحفظ.
- ربط Google Search Console يتطلب OAuth Client ID وClient Secret وRefresh Token مع صلاحية Search Console. زر الاختبار يجدد الرمز ويتحقق من الخاصية ويحاول إرسال خريطة الموقع الافتراضية.
- خريطة الموقع تحتاج إلى أن يكون WordPress هو الذي يخدم الموقع ومسار `/wp-sitemap.xml` متاحًا. اختبار API لا يضمن الفهرسة أو ترتيب الصفحات.
- حقول الأسعار تستخدم قواعد نصية دقيقة بصيغة `النص الحالي|النص الجديد`؛ افحص الواجهة بعد التعديل. بعض النماذج أو مكونات القالب قد تتطلب تكاملًا خاصًا إذا لم تستخدم علامات `data-oxygen-*`.


## التشغيل اليومي للمقالات الثابتة

النشر اليومي الفعلي للموقع الرئيسي `https://oxygen11.com` مستقل عن WP-Cron الخاص بووردبريس. سير عمل GitHub ينشر مقالًا واحدًا يوميًا في الساعة 01:19 UTC (04:19 صباحًا بتوقيت مصر)، ويحدّث قائمة المقالات و`sitemap.xml`، ثم يتحقق من وصول صفحة المقال وخريطة الموقع علنًا. آخر تشغيل ناجح تحقق من نشر مقال `ac-unusual-noise` على الموقع العام.

توجد حاليًا **12 مقالة مُراجعة** في `.github/article-queue/pending/` تُنشر بالتتابع، مقالًا واحدًا في كل تشغيل يومي، قبل محاولة توليد مقال جديد. بعد نفاد هذه القائمة، يحتاج الاستمرار التلقائي إلى `OPENAI_API_KEY` في **Settings → Secrets and variables → Actions** داخل مستودع GitHub. هذا السر غير موجود/غير متاح في إعداد التشغيل الذي ظهر في سجل التشغيل الفاشل؛ من دونه لا يختلق النظام مقالًا أو ينشر قالبًا عامًا، بل يتوقف برسالة واضحة. لا تضع مفتاح API في الملفات أو داخل المحادثات.

سجل فحص GitHub بتاريخ 24 أكتوبر 2026 أن كلا النطاقين `oxygen11.com` و`googl.oxygen11.com` يعيدان واجهة HTML ثابتة، وأن `/wp-login.php` و`/wp-admin/` و`/wp-json/` تعيد 404، وكذلك مسارات WordPress الشائعة. لذلك لم يتم إثبات وجود تثبيت WordPress متاح من هذه النطاقات حتى الآن. يلزم تصحيح مجلد الجذر/التثبيت في Hostinger قبل الاعتماد على REST أو بوابة الإدارة. عمليات نشر GitHub إلى Hostinger متوقفة لأن أسرار FTP المطلوبة غير مضبوطة في المستودع.


## تحويل التشغيل إلى WordPress

أضيف قالب WordPress باسم **Oxygen WordPress** داخل `oxygen-wp-theme/`. القالب يعرض واجهة أكسجين نفسها من داخل WordPress، ويستخدم تسجيل الدخول وصلاحيات WordPress للوصول إلى لوحة الناشر. صفحات WordPress والمقالات العادية تُعرض بقوالب القالب بدل صفحات PHP مستقلة.

**هذه الملفات ليست نسخة من WordPress Core.** لا يمكن إنشاء `/wp-admin/` أو `/wp-login.php` بمجرد إضافة قالب أو تعديل `.htaccess`: يجب وجود تثبيت WordPress حقيقي في مجلد جذر النطاق، مع `wp-admin/`, `wp-includes/`, `wp-login.php`, `wp-load.php`, `wp-blog-header.php`, `index.php` وقاعدة بياناته وملف `wp-config.php`. استخدم أداة Hostinger Auto Installer للموقع/النطاق الذي تريد تحويله، ولا ترفع ملفات نواة مجهولة ولا تستبدل قاعدة البيانات الحالية.

يُعدّل `.htaccess` الآن أولوية `DirectoryIndex` إلى `index.php` ثم `index.html`، حتى يتقدم WordPress على النسخة الثابتة عند وجود تثبيت فعلي. إذا كان `googl.oxygen11.com` يستخدم مجلدًا مستقلًا، فيجب أن يحتوي مجلد ذلك النطاق على تثبيت WordPress نفسه أو أن يُضبط Document Root على تثبيت قائم.

سير عمل **Deploy Oxygen plugin to Hostinger** يرفع الإضافة إلى `wp-content/plugins/oxygen-ac-automation/` والقالب إلى `wp-content/themes/oxygen-wp-theme/` في تثبيت WordPress نفسه. يرفع الملفات فقط ولا يثبت WordPress Core أو ينشئ قاعدة بيانات أو يُصلح مسار Document Root تلقائيًا.
